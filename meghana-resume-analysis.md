# Meghana H K

## Recruiter verdict

**Best fit:** Junior-to-mid-level DevOps Engineer, AWS DevOps Engineer, CI/CD Engineer or Cloud Automation Engineer.

**Current level:** Approximately three years of stated DevOps/cloud experience plus earlier QA experience. The resume needs clarification because the most recent job ended in August 2025.

**Interview recommendation:** Potential interview for junior-to-mid DevOps roles after metrics, certification wording, project provenance and the current employment gap are clarified.

## Detailed evaluation

### 1. First-impression clarity

**PROBLEM:** The summary is relevant but overly metric-heavy and difficult to scan due to abnormal spacing in the PDF.

**WHY IT MATTERS:** Recruiters may question the precision of the metrics before understanding the candidate's actual scope.

**EXACT FIX:** Lead with role, years, core stack and one strongest result. Move remaining metrics into experience.

### 2. Target role clarity

**PROBLEM:** The DevOps target is clear, but the resume does not state the intended seniority.

**WHY IT MATTERS:** The actual DevOps period is approximately three years.

**EXACT FIX:** Use `DevOps Engineer | AWS, Terraform, Jenkins, Docker and Kubernetes`, without `Senior`.

### 3. Professional summary

**PROBLEM:** The summary uses strong verbs such as `spearheaded` and `architected` without describing scale or team context.

**WHY IT MATTERS:** These words imply primary ownership.

**EXACT FIX:** Use `implemented` or `contributed to` unless the candidate can explain sole or lead ownership.

### 4. Technical skills

**PROBLEM:** Skills are broad and include terms not supported by experience, such as Prometheus, Grafana, Kubernetes, EKS, RBAC, SSL/TLS, NLB, VPC peering and EBS.

**WHY IT MATTERS:** Unsupported keywords weaken credibility.

**EXACT FIX:** Add factual project or job evidence for each major skill, or move it to foundational knowledge.

### 5. DevOps experience

**PROBLEM:** The TVS role contains relevant DevOps work, but nearly every bullet uses a percentage without explaining the baseline.

**WHY IT MATTERS:** The candidate's genuine work is overshadowed by questionable precision.

**EXACT FIX:** Keep only metrics that can be documented and explain how each was measured.

### 6. Cloud experience

**PROBLEM:** AWS service coverage is broad, but `27% enhancement in cloud security` is not a defined measurement.

**WHY IT MATTERS:** Security posture is not normally expressed as a generic percentage.

**EXACT FIX:** Replace it with the actual controls implemented, such as IAM policies, security groups, network ACLs, logging or remediation counts.

### 7. Kubernetes and containers

**PROBLEM:** Docker, Kubernetes and EKS appear in the summary and skills but not in professional experience or projects.

**WHY IT MATTERS:** This creates a substantial mismatch between branding and evidence.

**EXACT FIX:** Add genuine container build, Kubernetes deployment, EKS, RBAC or troubleshooting bullets. Otherwise remove these technologies from the summary.

### 8. CI/CD

**PROBLEM:** CI/CD is the strongest area, but similar 38% and 45% improvements appear in both professional experience and projects.

**WHY IT MATTERS:** It is unclear whether these are the same initiatives, duplicated metrics or unrelated work.

**EXACT FIX:** Identify project provenance and avoid reusing the same metric unless the project is explicitly part of the TVS role.

### 9. Infrastructure as Code

**PROBLEM:** Terraform experience includes VPCs, security groups, route tables and NAT gateways, but state, modules, environments and review process are missing.

**WHY IT MATTERS:** The current evidence supports basic-to-intermediate Terraform, not advanced IaC ownership.

**EXACT FIX:** Add backend, state locking, modules, variables, workspaces/environment strategy, validation and change-review details if used.

### 10. Security and observability

**PROBLEM:** CloudWatch monitoring is described, but Prometheus and Grafana are unsupported. Security outcomes are vague.

**WHY IT MATTERS:** Observability and security are high-value DevOps capabilities only when tied to real implementation.

**EXACT FIX:** Retain CloudWatch. Add Prometheus/Grafana only with dashboards, metrics, alert rules and operational outcomes. Replace the security percentage with concrete controls.

### 11. AI/GenAI

**PROBLEM:** No AI or GenAI evidence is present.

**WHY IT MATTERS:** The resume is not suitable for AI Engineering or LLMOps roles.

**EXACT FIX:** Do not add AI keywords unless a genuine project is completed and documented.

### 12. Project quality

**PROBLEM:** Projects are technically relevant but lack dates, links and labels showing whether they were professional, personal or training projects.

**WHY IT MATTERS:** The metrics overlap with work experience, making attribution unclear.

**EXACT FIX:** Add `Professional Project`, `Personal Project` or `Training Project` to each entry, plus GitHub links and dates.

### 13. Achievement statements

**PROBLEM:** Almost every role contains exact percentage improvements: 27%, 38%, 46%, 45%, 32%, 96%, 94%, 32% and 27%.

**WHY IT MATTERS:** An unusually dense pattern of precise metrics can look fabricated unless backed by reports.

**EXACT FIX:** Retain only metrics with a clear source, timeframe and formula. Convert the rest into factual scope or outcome statements.

### 14. Keyword relevance

**PROBLEM:** ATS keyword coverage is high, but several keywords lack evidence.

**WHY IT MATTERS:** The resume may pass automated screening and then fail recruiter or technical validation.

**EXACT FIX:** Prioritize demonstrated AWS, Jenkins, Terraform, CloudWatch, testing and CI/CD skills. Support or remove Kubernetes/EKS/Prometheus/Grafana.

### 15. ATS readability

**PROBLEM:** The PDF has abnormal spacing, a multi-column skills section and fragmented text extraction.

**WHY IT MATTERS:** ATS systems may parse phrases and skills incorrectly.

**EXACT FIX:** Use a single column, normal word spacing, plain bullets and a linear skills list.

### 16. Grammar and consistency

**PROBLEM:** Examples include `Canary Development`, `builds & manual deployment intervention`, inconsistent ampersands and excessive spacing.

**WHY IT MATTERS:** Incorrect technical terminology can affect keyword matching and reviewer trust.

**EXACT FIX:** Use `canary deployment` and rewrite the sentence as `Integrated Jenkins pipelines with GitHub webhooks, automating builds and reducing manual deployment intervention.`

### 17. Credibility

**PROBLEM:** `AWS Certified Solutions Architect – Micro Degree` may be interpreted as an AWS-issued certification even though MicroDegree appears to be the training provider.

**WHY IT MATTERS:** Certification issuer ambiguity can be perceived as misrepresentation.

**EXACT FIX:** Use the exact credential name. If it is a course, write `AWS Solutions Architect Training — MicroDegree`; use `AWS Certified Solutions Architect – Associate` only if AWS issued that certification.

**PROBLEM:** The last listed role ended in August 2025, creating an unexplained gap of approximately 13 months as of September 2026.

**WHY IT MATTERS:** Recruiters will ask about current status.

**EXACT FIX:** Add the current role, job search, training, caregiving or other factual activity with dates.

### 18. Unnecessary information

**PROBLEM:** Numerous percentages and duplicated CI/CD project statements crowd the resume.

**WHY IT MATTERS:** The document feels optimized rather than evidence-based.

**EXACT FIX:** Keep three to five strongest metrics and replace the rest with scope and technical detail.

### 19. Missing information

**PROBLEM:** Current status, project provenance, metric sources, GitHub links and Kubernetes implementation evidence are missing.

**WHY IT MATTERS:** These gaps directly affect employability and credibility.

**EXACT FIX:** Add all five before applying broadly.

### 20. Target-job alignment

**PROBLEM:** No JD was supplied.

**WHY IT MATTERS:** Exact keyword and requirement matching cannot be completed.

**EXACT FIX:** Target AWS DevOps, CI/CD and Terraform roles requiring approximately two to four years. Avoid senior SRE, platform and AI roles.
